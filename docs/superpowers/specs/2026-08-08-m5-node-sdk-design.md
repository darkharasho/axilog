# axilog — M5: Node SDK (napi-rs)

**Status:** Approved (autonomous continuation authorized by user 2026-08-08)
**Why:** The axi-suite end goal is axibridge/axipulse running on axilog instead of the EI CLI.
axibridge is an Electron/Node app — a native Node addon lets it call the Rust core in-process
(no CLI spawn, no .NET runtime download, no temp-file JSON round-trip).

## Scope

1. **`axilog-node` crate** (napi-rs, cdylib): functions
   - `parseFile(path, options?) -> Report` (native schema as a JS object)
   - `parseBuffer(bytes, options?) -> Report`
   - `parseFileEi(path) -> DPSReportJSON-shaped object` (the EI-compat adapter — axibridge's
     current contract, making adoption a config change)
   - `anonymizeFile(inPath, outPath)`
   options: reserved (empty struct now — versioned surface).
2. **TypeScript definitions** generated by napi-rs, checked in, with the Report type surface
   documented.
3. **Node-side tests** (plain `node:test`, no vitest — avoids the heavy dep) against the
   committed anon fixture: parse → assert schema_version, players count, squad damage total,
   a boon uptime, support sums; parseFileEi → assert EI shape keys axibridge reads
   (players[].dpsAll, support, buffUptimes, targets, wvWMapData).
4. **CI**: build the addon + run node tests on ubuntu (primary); build-only on
   windows/macos in the existing matrix.
5. **README + npm-shaped packaging metadata** (name `@axi/axilog` placeholder — publishing
   itself deferred; local `npm pack`-able).

## Correctness gates
- Node-reported numbers identical to the CLI's JSON for the committed fixture (byte-compare the
  serialized native Report through both paths).
- Rust workspace tests remain green; the addon crate is additive.

## Non-goals
Python SDK (M6), publishing to npm, async/streaming APIs, watch mode.
