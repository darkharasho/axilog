# axilog M5 — Node SDK Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development.

**Goal:** A napi-rs native Node addon (`axilog-node`) exposing parseFile/parseBuffer/parseFileEi/
anonymizeFile with generated TS types, node-side tests against the committed fixture, and CI.

**Architecture:** New cdylib crate wrapping the existing pipeline (decode_raw → resolve → analyze
→ build_report [→ to_ei_json]). Serialization boundary: serde_json Value → napi (or napi's serde
feature) — pick the simplest correct route and document it.

## Global Constraints

- Rust workspace stays green: `cargo test --workspace` (existing 188) after each task; the addon
  is additive — no changes to existing crates beyond workspace membership.
- Node toolchain: use whatever node is on PATH (verify `node --version` ≥ 18); tests via
  `node --test` (no vitest/jest — keep the dep surface zero). If npm deps are unavoidable
  (@napi-rs/cli for builds), pin them in the addon's package.json only.
- The committed fixture `fixtures/wvw-small.anon.zevtc` is the test log everywhere.
- MIT; warning-free Rust; addon crate named `axilog-node`, npm name `@axi/axilog` (placeholder).

### Task 1: napi-rs crate + bindings

**Files:** Create `crates/axilog-node/` (Cargo.toml cdylib + napi deps, `src/lib.rs`,
`build.rs`, `package.json`, `.npmignore`), modify workspace `Cargo.toml`.

**Requirements:**
- napi + napi-derive (latest 2.x/3.x — check what's current; `napi build` via @napi-rs/cli).
- Exports: `parseFile(path: string) -> Report-as-JS-object`, `parseBuffer(buf: Buffer)`,
  `parseFileEi(path: string)`, `anonymizeFile(inPath: string, outPath: string)`. Errors map to
  JS exceptions with the Rust error text (no panics across FFI — catch/convert).
- Serialization: native `Report` serde-serializes; route through napi's serde-json interop
  (`napi/serde-json` feature: return `serde_json::Value` or typed) — verify which napi feature
  produces plain JS objects (not strings). parseFileEi returns the adapter's Value.
- `cargo build -p axilog-node` compiles; `npx napi build --platform` (or equivalent) produces a
  loadable `.node`; smoke-load it from node REPL in the task (document the command used).

### Task 2: TS types + node tests + dual-path parity

**Files:** `crates/axilog-node/index.d.ts` (generated + committed), `crates/axilog-node/__test__/sdk.test.mjs`,
`crates/axilog-node/README.md`.

**Requirements:**
- Generated TS definitions committed; a doc comment block describing the Report surface.
- `node --test` suite: parseFile(committed fixture) asserts schema_version "0.1", players len,
  squad damage total 2,138,414, one boon uptime value, support sums (801/97/437/6 squad totals);
  parseBuffer equivalence; parseFileEi asserts the axibridge-read keys (players[].account,
  dpsAll[0].damage, support[0].condiCleanse, buffUptimes non-empty, targets[].enemyPlayer,
  wvWMapData team ids); anonymizeFile round-trip (tmp output parses identically).
- Dual-path parity: JSON.stringify(node Report) equals the CLI's `--format json` output parsed+
  re-stringified (same ordering via serde) — or a field-by-field deep-equal if key order differs.
- Wire an npm script (`npm test`) and document `npm run build && npm test`.

### Task 3: CI + docs

**Files:** `.github/workflows/ci.yml`, root `README.md`.

**Requirements:**
- CI: on ubuntu, add addon build + `node --test` step (setup-node@v4, node 20); windows/macos

- Root README: SDK section with a short Node usage example (parse + read a few fields, parseFileEi
  for EI-shaped output), M5 milestone entry, note that npm publishing is deferred.
- Confirm whole CI would pass: run the exact CI steps locally (cargo build/test + napi build +
